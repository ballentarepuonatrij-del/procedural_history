# Фэнтези: летопись мира

Прототип генератора фэнтезийной истории для **Windows 10/11**, классический **Win32 Desktop / GDI**, **C++20**, без сторонних библиотек. Проект рассчитан на **Visual Studio 2026** с рабочей нагрузкой «Разработка классических приложений на C++», инструментами CMake и установленным Windows 10/11 SDK. Сборка использует доступный компилятор MSVC и SDK из вашей установки Visual Studio.

## Запуск из Visual Studio

1. Распакуйте архив и откройте папку `FantasyChronicle` в Visual Studio: **File → Open → Folder**.
2. Выберите CMake-предустановку **windows-debug** (или **windows-release**). В Visual Studio должны быть установлены компоненты C++ для классических приложений и CMake/Ninja.
3. Выберите запускаемый объект `FantasyChronicle.exe` и запустите его (**F5** или **Ctrl+F5**).
4. Если IDE не подхватила предустановки, откройте терминал **Developer PowerShell for VS** в папке проекта:

   ```powershell
   cmake -S . -B out/build/manual -G Ninja -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=OFF
   cmake --build out/build/manual --config Release
   .\out\build\manual\FantasyChronicle.exe
   ```

Исходники в UTF-8; для MSVC задан ключ `/utf-8`. Для линковки достаточно стандартных системных библиотек `user32`, `gdi32`, `comctl32`, `comdlg32`, `advapi32`.

## Исправление мерцания карты при перемещении

Главное окно теперь выводится с **двойной буферизацией GDI (double buffering)**. Перед отображением кадра весь фон, карта, границы провинций, подписи и легенда отрисовываются во вспомогательном bitmap в памяти (`CreateCompatibleDC` + `CreateCompatibleBitmap`), после чего изображение за одну операцию `BitBlt` переносится на экран. Это предотвращает видимые промежуточные состояния (пустое окно, частично нарисованная карта) при перетаскивании мышью. Буфер переиспользуется между кадрами и пересоздаётся при изменении размеров главного окна; его GDI-объекты освобождаются при выходе. Во время перемещения карты инвалидируется только прямоугольник карты, а при смене масштаба — весь интерфейс для обновления надписи масштаба. Если создать bitmap не удаётся, остаётся резервная отрисовка напрямую.

**Проверка на Windows:** зажмите ЛКМ и быстро перемещайте карту при масштабах 100%, 200% и 600%; затем несколько раз измените размер главного окна и переключите слой «Государства / Провинции / Регионы». Карта, надписи и боковая панель не должны мигать или временно пропадать. Система моделирования истории не затрагивалась этим исправлением.

## Новое: целая планета, провинции и географические регионы

**Планетарная география.** `World::planet()` описывает единую сферическую планету **Эйтар** (условный радиус 6200 км, наклон оси 23,5°). Генерация охватывает всю поверхность от северного до южного полюса. 2D-карта — развёртка по широте и долготе, а не отдельно вырезанный участок континента: долгота меняется от −180° до +180°, **западный и восточный край соединены**. Материки и острова могут пересекать этот стык. При перемещении ЛКМ карта горизонтально закольцована, метки поселений и выбор территории совпадают с проекцией. По вертикали за полюсами карта не продолжается.

**Биомы.** Высоты и влажность теперь генерируются периодическим по долготе шумом, а широта влияет на температуру. Помимо морей, равнин, лесов, джунглей и гор есть **пустыни, тундра и ледяные пустоши**. Это условная климатическая модель, а не физическая симуляция погоды или тектоники плит.

**Территориальная иерархия:** **планета → материки/острова → регионы → провинции → клетки**. Материки формируются по связности суши с учётом линии ±180°; провинции формируются как цельные смежные области суши, регионы объединяют смежные провинции. Их географические границы и ID не меняются в исторических эпохах. Государственные границы меняются **целыми провинциями**, а не отдельными пикселями; это основа для будущей экономики, ресурсов, крепостей, феодальных владений и управления по провинциям. При рождении государства оно получает стартовые провинции, при расширении или восстании может переходить целая провинция. Небольшие острова тоже получают свои провинции.

**Три слоя карты:** над легендой справа находится кнопка `Слой: Государства` — циклически переключает политическую карту, провинции и регионы. В политическом слое ЛКМ по земле открывает страну, в слое провинций — историю провинции, в слое регионов — сведения о регионе и списке его провинций с владельцами в выбранный год. **Ctrl+ЛКМ** в региональных слоях открывает владельца как государство. Клик по значку поселения открывает его летопись на любом слое. Зум и перетаскивание работают во всех слоях.

**История территорий.** У каждой провинции есть годовой `ProvinceYear` (владелец, развитие, беспорядки, число поселений); `ProvinceEvent` фиксирует передачу её власти. В окне провинции отображаются материк, регион, биом, широта и долгота, состояние в выбранный год и список переходов власти. В окне региона показаны все его провинции и их владельцы. При перемотке года связи провинций сохраняются, а владельцы и местные показатели переключаются. В TXT-экспорт включены географическая структура и хронология провинций.

**Важные ограничения:** планета представлена двумерной широтно-долготной развёрткой, **не 3D-глобусом**. Полярные ячейки упрощены (не сходятся в одной точке), площади клеток пока не равны в квадратных километрах. Географические регионы — **постоянные физико-географические области**, а не автоматически изменяемые административные единицы внутри государства. Названия процедурные, условные. Сохранение симуляции по-прежнему выполняется через зерно + параметры, не через отдельный файл сохранения. Генератор пересоздаёт мир с той же случайной последовательностью для конкретной версии, но переход между версиями не гарантирует неизменность карты для старого seed.

## Ранее добавлено: родословные, семьи и наследование

**Связи поколений.** Все жители имеют уникальные ID; жители стартового поколения создают собственные именованные роды (`Family`). В истории мира возникают заключённые браки (`Marriage`) и реальные дети двух существующих совершеннолетних жителей. У ребёнка сохраняются ID обоих родителей, принадлежность к одному из родительских родов и список детей у родителей. Браки не стираются после смерти, а вдовство и повторный брак учитываются по годам. Браки между близкими родственниками запрещены.

**Наследственные способности.** Способности и черты характера новорождённого рассчитываются из врождённых показателей обоих родителей с ограниченным случайным отклонением. Навыки не копируются генетически: ребёнок получает образование от живого родителя, а к совершеннолетию может выбрать ремесло одного из родителей. Все изменения сохраняются в прежних годовых снимках `CharacterYear`, так что перемотка не показывает будущее.

**Имущество и династии.** У жителя есть условное имущество в монетах, которое меняется с работой и расходами и фиксируется в летописи. После смерти оно передаётся живым детям поровну, а при их отсутствии — живому супругу или супруге. Все передачи учитываются как `Inheritance` и отображаются в биографиях. При вакантном **монархическом** престоле взрослые потомки прежнего правителя имеют приоритет над посторонними кандидатами; в республиках и теократиях действует обычный выбор по качествам.

**Родословная в окне жителя.** В правой панели видны семья/род, два родителя, действующий в выбранный год супруг, известные предки до трёх поколений, дети, родившиеся к указанному году, и личное имущество. В TXT-экспорт включены роды, браки и наследства.

**Размер и положение окна.** При первом запуске главное окно открывается **по центру** и занимает **80% рабочей области основного монитора** (с учётом панели задач). Изменённые размер, положение и режим максимизации сохраняются в реестре текущего пользователя `HKEY_CURRENT_USER\Software\FantasyChronicle` (значение `MainWindowPlacement`) при перемещении/изменении размера и при закрытии. При последующих запусках они восстанавливаются; если монитор отключён, окно возвращается в видимую область. Чтобы вернуть настройку первого запуска, удалите значение `MainWindowPlacement` в реестре (при закрытом приложении). Сохраняются только настройки **главного окна**, не состояние сгенерированного мира и не позиции вспомогательных окон.

**Ограничения этапа:** у стартовых жителей неизвестны их предки до начала симуляции (не выдумываются); пары сейчас заключают браки, но разводы, усыновления и сложная наследственная юриспруденция пока не моделируются. Роды являются идентификаторами линий происхождения, а не полноценными феодальными владениями. Имущество выражено условными монетами. Рождение моделируется для существующих супружеских пар; это упрощение демографии, не модель реальной репродукции.

## Использование

- На карте используйте кнопку **«Слой: Государства / Провинции / Регионы»** для выбора уровня детализации. В провинциальном и региональном слоях ЛКМ открывает соответствующую территорию; **Ctrl+ЛКМ** — государство-владелец.
- В стартовом экране выберите **1–28 стартовых цивилизаций**, **1–400 лет** и **зерно** генератора. При одинаковых значениях зерна и параметров мир воспроизводится идентично.
- Нажмите **«Создать мир»**. Симуляция рассчитывает историю на выбранный период и сохраняет снимок мира для каждого года.
- Окраска карты показывает текущие границы государств и области влияния. **Колёсико мыши** над картой меняет масштаб (100–1200%); увеличение привязано к точке под курсором. **Зажатая ЛКМ + перемещение** двигают карту, не открывая окна по окончании перетаскивания; долгота закольцована.
- **Короткий щелчок ЛКМ** по окрашенной области открывает окно государства с культурой, правлением, населением и хронологией. **Щелчок по круглой метке** открывает **отдельную историю поселения** (города, деревни, замка, рощи, горного города, лагеря или скрытой общины). При масштабе от 200% появляются подписи поселений.
- В окне поселения показаны место, год основания, первоначальный и текущий владелец, благосостояние по выбранному году, список именных уроженцев и **собственная летопись**: строительство, ремёсла, ярмарки, бедствия, нападения, смена государственной принадлежности. На шкале времени эта информация обновляется одновременно с политическими границами.
- Если на карте слишком тесно и трудно выбрать точку, приблизьте карту колёсиком. Если государство исчезло, история его поселений не пропадает; в выбранном году они могут иметь другого владельца или быть независимыми.
- В окне государства выберите **жителя**, чтобы увидеть его профессию, социальное положение, членство в объединениях, **характеристики на выбранный год**, начальные параметры и личную биографию. Можно включить **умерших** жителей.
- Перемещайте **ползунок**, нажимайте **«◀ Год» / «Год ▶»** или **«▶ Пуск»**: карта, население, страна, правитель, поселения и биографии переключаются в выбранный год.
- **«Летопись в TXT»** сохраняет государства, их события, **отдельные летописи поселений** и биографии в UTF-8. **«Новый мир»** возвращает к стартовым условиям.

### Базовая модель

- **Расы и культуры**: люди (античные государства, торговля и рабский труд), эльфы (леса, оборона), дварфы (горы, ремёсла и рабские рейды), разбойники/пираты (стоянки и картели), сказочный народец (лесные общины).
- **Мир**: вся поверхность планеты с долготно-широтной проекцией; материки, острова, равнины, леса, джунгли, пустыни, тундра, ледяные земли и горы. Каждая сухопутная клетка входит в неизменную провинцию; государство владеет провинцией целиком или не владеет ей.
- **Политика**: различные формы правления; расширение и потеря территорий; восстания с образованием новых государств; смена правителей.
- **Экономика и общества**: казна, устойчивость, торговые связи, поселения, ремесленные гильдии и контрабандные картели, рабство, освобождение.
- **Индивидуальная жизнь**: у каждого жителя есть ID, имя, раса, рождение, смерть, этапы профессии/сословия/государственной принадлежности, родное поселение, биография. **Характеристики** включают 6 способностей (сила, ловкость, интеллект, харизма, выносливость, сила воли), 8 навыков (военное дело, ремесло, торговля, знания, дипломатия, выживание, скрытность, целительство) и 5 черт характера (смелость, любознательность, честолюбие, сочувствие, дисциплина). Все показатели имеют диапазон 0–100, фиксируются при создании личности и развиваются по годам с историческими снимками `Person::development`. Опыт профессии, достижений, поездок, наставничества, личных отношений, пленения и освобождения меняет характеристики; накопленное лидерство влияет на выбор правителя. Есть взаимодействия **двух конкретных людей** (дружба, брак, соперничество, деловой союз, наставничество, преступление) с записью в обе биографии.
- **История**: для каждого года сохраняются карта территорий, состояние государств и **состояние существующих поселений**. Кроме того, каждый живой персонаж сохраняет показатели в конце каждого прожитого в симуляции года; умершие сохраняют последний известный снимок. Поселение хранит неизменный ID, координаты, основателя, вид и год основания; `SettlementYear` содержит владельца, благосостояние и число поимённо учитываемых уроженцев на каждый год. Местные события хранятся отдельно как `SettlementEvent`; смена владельца определяется при создании годового снимка даже после действий модулей. Можно отматывать время без повторного расчёта.
- **Интерактивная камера**: `fantasy::MapCamera` хранит масштаб и центр в мировых координатах; все метки, границы и обработка щелчков используют одну проекцию. Долгота циклична; полярные широты ограничены; визуальные копии мира соединены у линии ±180°.

### Пределы прототипа

Это **работающий каркас**, а не законченный симулятор всех социальных процессов. Демография моделируется индивидуально, но с ограничением порядка **95–220 одновременно живущих персонажей на одно государство**, чтобы вся история оставалась доступной в памяти. Площадь клеток не переведена в реальные квадратные километры; экономика, благосостояние поселений и дипломатия пока вероятностные. **Отдельная модель адреса текущего проживания пока отсутствует:** список персонажей в окне поселения — уроженцы по привязке `homeSettlement`, а поле «учтённых уроженцев» считает тех из них, кто жив и числится в государстве, контролирующем поселение. Это не полная перепись фактического населения города. Названия/тексты генерируются из шаблонов, а не языковой моделью. Нет сложной генетики (только вероятностная наследуемость характеристик), товаров, маршрутов армий, полноценного поведения отдельного ИИ и сохранения симуляции в редактируемом формате. Экспорт TXT содержит летопись и биографии; для восстановления карты используйте те же начальные параметры и зерно.

**Модульный API уже работает:** реализован интерфейс `fantasy::IWorldModule` с хуками `onWorldCreated(World&)` и `onYear(World&, int)`, регистрация через `World::registerModule(...)`. Модуль может читать состояние через `liveOwners()`/`liveStates()` и расширять его с помощью `publishEvent`, `publishSettlementEvent`, `alterNation`, `claimTile`, `addPersonNote`, `grantExperience` (во время `onYear`, до сохранения снимка года). Пример в `examples/MagicPortentsModule.h` добавляет магическое знамение каждые 25 лет. Чтобы включить его, вызовите `world.registerModule(std::make_unique<MagicPortentsModule>());` перед `generate()` (например, в `Application::startGeneration`).

Для следующей версии логично добавить более богатые интерфейсы модулей (экономика, магия, религии, болезни, торговые пути) и бинарный/SQLite-формат сохранения снимков и персонажей.

## Проверка на Windows

1. Создайте мир и наведите мышь на середину карты; поверните колёсико вверх и вниз — участок под курсором должен оставаться примерно на месте, пока это позволяет край карты.
2. На масштабе 200% зажмите ЛКМ и потяните карту. Окно подробностей при перетаскивании не должно открываться; при перемещении через правый/левый край появится противоположная сторона планеты.
3. Щёлкните по круглой точке поселения: откроется его история. Щёлкните вне точки, внутри цветного государства: откроется история государства.
4. Не закрывая окно поселения, передвиньте шкалу годов: год, владелец, благосостояние и хроника должны измениться; более поздние события не должны быть видны в раннем году.
5. В окне государства выберите жителя и сравните характеристики при разных годах. Профессиональные навыки должны расти, события — влиять на черты характера, будущие изменения не должны появляться в прошлом. Умершие сохраняют показатели последнего года жизни.
6. Проверьте раздел «Родословная и семья» у ребёнка, родившегося после года 0: оба родителя существуют, они видны в списке предков, а дети не появляются в годах до собственного рождения. Попробуйте перемотать историю, сравнить имущество и посмотреть наследство после смерти родителя.
7. Измените размер и переместите главное окно, закройте приложение и откройте снова. Окно должно восстановить своё положение. При сбросе `MainWindowPlacement` оно снова должно появиться в центре с размером 80% рабочей области.
8. Убедитесь, что текст в летописи прокручивается без наложений, и проверьте экспорт TXT — в нём есть разделы «Роды и династии», «Браки и наследства», а также итоговые характеристики жителей.

## Тесты

На Windows можно запустить `FantasySmoke` или `ctest --test-dir out/build/windows-debug --output-on-failure`. Логика `FantasyCore` дополнительно собирается обычным C++20-компилятором на Linux для проверки независимости от Win32; само графическое приложение требует Windows.

## Развитие персонажей (новое)

- `Person::innate` — исходный профиль; `Person::current` — рабочий профиль текущего расчёта; `Person::development` — упорядоченные годовые записи `CharacterYear`. `World::statsAt(person, year)` возвращает профиль в историческом году, не раскрывая будущее.
- Обучение зависит от профессии, дисциплины и любознательности. При получении другой профессии меняется направление развития. Человек может сменить профессию по накопленному опыту; рабство и возраст ограничивают возможности обучения.
- В биографию записываются крупные жизненные рубежи и личные эпизоды. Небольшие ежегодные изменения фиксируются в характеристиках, чтобы летопись не засорялась повторяющимися строками.
- Интерфейс дополнений `World::grantExperience(personId, year, LifeExperience)` меняет характеристики при событиях из внешних модулей; вызывать его следует внутри `onYear`, пока рассчитывается соответствующий год. Для пояснения события можно отдельно использовать `addPersonNote`.
- Это **правила-приближения**, а не полноценная психологическая модель личности; здоровье, школьное обучение и сложные механизмы наследования предстоит развивать отдельно; семейное воспитание и простая наследуемость уже доступны.
